# 오목 추가 기획서

작성일: 2026-10-23 · 상태: 1차 구현 완료 · 방향키 + Space 조작

## 1. 기획 방향

**화면 한쪽에서 AI와 연습하거나, 같은 Wi-Fi의 동료에게 대결을 신청해 즐기는 1:1 오목.**

기존 게임 목록에 `오목`을 추가하고 `혼자하기`와 `대결`을 제공한다. 손그림 스타일과 빠른 진입 흐름을 유지하되, 보드와 돌은 작게 표시해도 명확하게 구분한다. 별도 계정이나 서버 없이 동작한다.

이 문서의 규칙과 수치는 초기 제안값을 포함한다. 구현에서는 기존 320×280 창을 유지하고, 메뉴까지 방향키와 Space로 조작한다. 우선 기본 오목의 완성도와 착수 안정성을 확보하고, 경쟁 규칙이나 랭킹은 후속 범위로 둔다.

## 2. 모드 구성

| 항목 | 혼자하기 | 대결 |
| --- | --- | --- |
| 상대 | 기기 내부 AI | 같은 Wi-Fi/LAN의 다른 사용자 1명 |
| 시작 | 난이도 선택 후 즉시 시작 | 기존 상대 검색 → 초대 → 수락 |
| 흑·백 | 첫 판 무작위 배정 | 호스트가 무작위 배정해 공유 |
| 다음 판 | 즉시 다시하기, 흑백 교대 | 양쪽 재대결 동의 후 흑백 교대 |
| 시간 제한 | 없음 | 첫 버전은 없음 |
| 무르기 | 제공 | 제공하지 않음 |
| 네트워크 | 불필요 | 기존 1:1 통신 사용 |

공통 모드 버튼 `혼자하기 / 같이하기`를 다른 게임과 똑같이 사용한다. 오목만 문구를 바꾸지 않는다.

## 3. 기본 규칙

- 15×15 교차점에 흑·백 돌을 번갈아 둔다. 흑이 먼저 둔다.
- 가로·세로·양쪽 대각선 중 한 방향으로 **5개 이상** 연속 연결하면 승리한다.
- 첫 버전은 **금수 없는 자유룰**이다. 흑·백 모두 3·3, 4·4, 6목 이상을 허용한다.
- 이미 돌이 있는 곳, 판 밖, 자기 차례가 아닌 경우에는 둘 수 없다. 패스는 없다.
- 마지막 빈칸에 둔 수가 승리 조건을 만족하면 승리, 그렇지 않으면 무승부다.
- 기권하면 상대 승리. 실수 방지를 위해 기권은 한 번 확인한다.
- 대국 시작 전 `자유룰 · 5개 이상 연결 · 금수 없음`을 명시한다.

자유룰에서는 선공의 유리함을 완전히 제거하지 않는다. 첫 판 무작위 배정과 재대결 시 흑백 교대로 캐주얼 대결을 구성한다. 렌주 금수 및 오프닝 교환 규칙은 별도 규칙 모드로 추후 검토한다.

## 4. 이용 흐름

### 혼자하기

`오목 선택 → 혼자하기 → 난이도 선택 → 대국 → 결과 → 다시하기 / 나가기`

- 기본 난이도는 `보통`. 마지막 선택은 앱 실행 중 유지한다.
- 대국 상단에 내 돌 색과 난이도를 표시한다.
- AI가 둘 때는 `AI가 생각 중…`을 표시하고 추가 착수를 막는다.
- 무르기는 **내가 마지막으로 둔 수 직전**으로 돌아간다. AI가 응수했다면 AI 수와 내 수를 함께 취소한다.
- AI 계산 중 무르기를 누르면 계산을 취소하고 내 수를 되돌린다. AI가 흑으로 둔 첫 수만 있는 경우에는 무르기를 비활성화한다.
- 무르기는 횟수 제한 없이 진행 중에만 제공한다. 종료 후에는 다시하기로 시작한다.
- 혼자하기에서 오버레이를 숨기면 AI 진행을 일시정지하고, 다시 표시하면 이어간다. 기존 숨김 이벤트와의 연동이 필요하다.

### 대결

`오목 선택 → 같이하기 → 상대 선택·초대 → 상대 수락 → 대국 → 결과 → 재대결 요청 / 나가기`

- 초대받은 사용자는 게임 이름과 자유룰 안내를 확인한다.
- 시작할 때 `흑: 닉네임 / 백: 닉네임`을 표시한다. 초대한 사람이 항상 선공을 갖지 않는다.
- 내 차례에는 착수 가능 위치를 미리 보여주고, 상대 차례에는 `상대 차례`를 표시한다.
- 재대결은 양쪽이 동의해야 시작한다. 한쪽만 누르면 `상대의 재대결 동의를 기다리는 중`을 표시한다.
- 상대가 나가면 재대결 대기를 해제하고 목록으로 돌아갈 수 있게 한다.
- 대결 중 오버레이 숨김은 대국을 멈추지 않는다. 돌아오면 최신 보드를 보여준다.

## 5. 화면과 조작

보드는 옅은 종이색의 불투명 배경, 얇은 손그림 격자, 선명한 흑·백 돌로 구성한다. 백돌에는 외곽선을 넣고, 장식 때문에 실제 착수 위치가 흔들리지 않게 한다.

```text
 오목 · 자유룰                 [나가기]
 ● 나          내 차례         ○ 상대

         A B C D E … O
      1  ┌─────────────┐
      2  │             │
      …  │  15 × 15    │
     15  └─────────────┘

 마지막 수 H8 · 17수
 [무르기: 혼자하기만]            [기권]
```

- 보드 전체가 잘리지 않는 정사각형 레이아웃. 기본 320×280 창에서는 교차점 간격 14 CSS px로 표시하고 창 크기에 맞춰 비례 확대한다.
- 마우스 착수 없이 키보드만 사용한다. 기존 게임의 손그림 선과 잉크·종이색을 재사용한다.
- 키보드: 방향키로 선택 위치 이동, Space로 착수. 시작 선택 위치는 중앙, 이후에는 마지막 선택 위치를 유지한다.
- Space는 키를 누를 때 한 수만 발생한다. 길게 눌러도 추가 수가 들어가지 않는다. 방향키는 길게 누르면 연속 이동한다.
- 마지막 수는 작은 테두리 표시, 승리한 연결은 선으로 강조한다. 무승부와 기권도 별도 결과 문구를 사용한다.
- 네트워크 착수 확인 중에는 해당 위치를 반투명으로 표시하고 `착수 확인 중`을 보여준다. 확정 전 다른 위치에 둘 수 없다.
- 결과가 나와도 보드는 남겨두고 `승리 / 패배 / 무승부`와 다시하기·재대결 버튼을 표시한다.
- 효과음은 기존 앱 정책에 맞춰 적용 여부를 결정하며, 첫 버전에서 필수로 두지 않는다.

## 6. AI 설계

별도 API나 모델 다운로드 없이 로컬에서 계산한다. 같은 규칙 엔진으로 가능한 수와 승패를 판정한다.

| 난이도 | 의도 | 착수 전략 |
| --- | --- | --- |
| 쉬움 | 기본 연결을 익히는 상대 | 즉시 승리·즉시 패배 방어 우선, 그 외 상위 후보에서 무작위 선택 |
| 보통 | 공격과 방어를 고민할 상대 | 열린 3·4와 양방향 위협 평가, 제한된 깊이 탐색 |
| 어려움 | 몇 수 앞을 읽는 상대 | 후보 정렬, 반복 심화와 알파베타 탐색, 복수 위협 우선 평가 |

- 돌 주변의 빈칸을 중심으로 후보를 줄인다. 빈 보드에서는 중앙에 둔다.
- 어떤 난이도든 즉시 승리할 수 있는 수를 우선한다. 그렇지 않으면 상대의 다음 수 승리를 막되, 동시에 여러 위협이 생겨 방어가 불가능할 수도 있다.
- 계산과 화면 갱신을 분리한다. Web Worker 등을 사용해 생각하는 동안 창 이동·숨김·나가기가 멈추지 않게 한다.
- 계산 예산 초안은 쉬움 100ms, 보통 300ms, 어려움 800ms. 실제 기기에서 조정하며, 예산이 끝나면 확보한 최선의 합법 수를 사용한다.
- 너무 즉각적인 응답을 피하기 위한 표시 지연은 약 250ms. 계산 시간에 불필요한 지연을 추가하지 않는다.
- 무르기·재시작·나가기 이후 도착한 이전 AI 계산 결과는 대국 ID와 보드 버전으로 무시한다.
- 난이도 이름은 상대적인 수준이며, 대회 수준 실력이나 특정 기력을 보장하지 않는다.

## 7. 대결 동기화와 예외 처리

기존 대결은 UDP 통신을 사용한다. 오목은 한 수가 누락되면 대국 전체가 달라지므로, 단순 입력 전달보다 **호스트가 확정한 보드 공유**를 중심으로 구성한다.

- 호스트만 착수 유효성과 승패를 최종 확정한다. 게스트는 좌표와 명령 번호를 요청한다.
- 요청에는 대국 ID, 턴 번호, 명령 번호, 좌표를 포함한다. 보낸 사람의 돌 색은 연결 정보로 판정한다.
- 상대 차례의 요청, 범위 밖·비정수 좌표, 이미 사용한 명령, 이전 대국의 요청은 거부한다.
- 게스트는 수신 확인 전까지 같은 요청을 재전송한다. 중복 수신해도 한 번만 처리한다.
- 전체 보드, 흑백 배정, 차례, 마지막 수, 결과, 보드 버전, 처리한 명령 번호를 호스트가 주기적으로 전송한다.
- 225칸 보드는 작은 고정 길이 표현으로 직렬화한다. 실제 패킷 크기는 기존 전송 경로의 한도와 함께 확인한다.
- 게스트는 이전 버전의 상태를 버리고 최신 상태만 반영한다. 잘못된 요청에는 거부 응답 또는 최신 상태를 돌려줘 입력 대기를 해제한다.
- 착수가 없는 동안에도 통신을 유지한다. 현재 1:1 경로는 약 3초간 상대 통신이 없으면 연결 종료로 판단하므로, 생각 중 패킷 전송을 멈추면 안 된다.
- 명시적인 기권은 패배로 확정한다. 기권 확정은 응답을 확인한 뒤 종료할 수 있게 한다.
- 통신 두절·앱 종료는 `연결 종료로 대국 중단`으로 표시한다. 첫 버전에는 자동 재접속과 대국 복구를 제공하지 않는다.
- 승패 확정 후 연결이 끊겨도 이미 확정한 결과를 중단으로 덮어쓰지 않는다.
- 재대결 시 새 대국 ID를 부여하고 이전 착수·AI 계산·결과 메시지를 무효화한다.

## 8. 기존 코드에 붙이는 방식

현재 `GameModule`이 `createSoloMatch`와 1:1 `createMatch`를 지원하므로 같은 오목 엔진을 두 모드에서 공유한다. `tower`의 교대 대결 및 명령 확인 흐름을 참고하되 물리 엔진은 필요 없다.

| 위치 | 변경 역할 |
| --- | --- |
| `src/renderer/games/gomoku/types.ts` | 보드, 좌표, 돌 색, 차례, 결과, 명령 타입 |
| `…/engine.ts` | 착수 검증, 승리·무승부 판정, 수 기록, 무르기 |
| `…/bot.ts`, `…/bot-worker.ts` | AI 평가·탐색과 계산 취소 |
| `…/input.ts`, `…/draw.ts` | 방향키·Space, 보드·돌·선택·승리선 표시 |
| `…/wire.ts` | 착수 요청·확인, 상태 검증, 직렬화 |
| `…/module.ts` | 혼자하기·대결 연결, HUD, 결과·재대결 상태 |
| `src/renderer/games/registry.ts` | 게임 목록에 오목 등록 |
| `src/renderer/shell/main.ts`, `games/types.ts` | 오목 모드 문구·설정, 숨김 연동, 결과 유지에 필요한 확장 |

현재 셸은 `isOver()`가 참이면 즉시 매치를 정리한다. 따라서 **보드의 승패 확정과 매치 화면 종료를 분리**해야 한다. 오목 결과 상태에서는 보드와 통신을 유지하고, 명시적으로 나갈 때 정리한다. 재대결도 이 상태에서 양측 동의를 교환한다. 연결 종료 콜백의 즉시 정리 동작 역시 결과 화면을 유지할 수 있도록 검토한다.

AI 난이도는 혼자하기 설정으로만 노출한다. 공통 `variants`를 그대로 쓰면 대결에서도 난이도가 보일 수 있으므로 모드별 설정 표시를 지원하거나 오목 전용 시작 패널을 둔다. 기존 게임의 기본 동작은 유지한다.

게임 ID를 별도로 열거한 통계·검증 코드도 확인해 `gomoku`를 반영한다. 웹 체험판 노출은 첫 구현 범위와 분리한다.

## 9. 첫 버전 범위와 개발 순서

1. **규칙 엔진**: 15×15 자유룰, 착수 기록, 승패·무승부·기권, 테스트.
2. **보드와 혼자하기**: 방향키·Space 조작, AI 3단계, 무르기, 결과·다시하기.
3. **대결**: 기존 초대 연결, 흑백 배정, 착수 확인·재전송, 연결 중단, 합의 재대결.
4. **통합 점검**: 작은 창과 고해상도 화면, 숨김·복귀, 게임 전환, 기존 게임 회귀 확인.

첫 버전에서 제외: 렌주 금수, 제한시간·초읽기, 랭킹, 인터넷 원격 매칭, 관전, 채팅, 기보 저장·복기, 대결 무르기, 같은 기기 2인 대결.

## 10. 완료 기준

- 두 모드 모두 처음부터 결과 확인과 다음 판까지 진행할 수 있다.
- 가로·세로·양 대각선, 가장자리, 5목·6목 이상, 마지막 칸 승리·무승부를 정확히 판정한다.
- 빈칸이 아닌 위치와 자기 차례가 아닌 입력은 보드를 바꾸지 않는다.
- AI가 합법적인 수를 두고, 즉시 승리와 단일 즉시 패배 위협에 대응한다.
- AI 계산 중 무르기·나가기·다시하기를 해도 이전 결과가 새 보드에 반영되지 않는다.
- 두 앱에서 지연·패킷 손실·중복·순서 역전을 주어도 같은 보드와 결과로 수렴한다.
- 마지막 승리 수가 담긴 패킷이 유실되어도 재전송으로 결과가 양쪽에 표시된다.
- 재대결은 양쪽 동의 후 한 번만 시작하고, 흑백이 교대되며 이전 대국 패킷을 무시한다.
- 숨김·복귀, 연결 종료, 결과 화면에서 나가기 이후 입력 이벤트·Worker가 남지 않는다.
- 작은 창에서 225개 교차점을 구분하고, 방향키와 Space로 원하는 곳에 둘 수 있다.
- 빌드와 오목 엔진·AI·통신 테스트, 실제 두 창 대결 점검 및 필요한 기존 테스트를 통과한다.
